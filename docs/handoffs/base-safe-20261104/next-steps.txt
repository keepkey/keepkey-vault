The bundle contains the Safe EIP-712 owner approval, eight Safe settings
functions, and the native Base USDC transfer. It authorizes descriptions,
not wallet transactions. Other tokens and protocols need their own definitions.
The Base USDC definition uses the signed unit formatter (USDC, six decimals)
and explicitly shows "unit set by signer" plus the raw amount. Its address
comes from Circle's official contract list; symbol and decimals were checked
on Base. It does not depend on a firmware token-table entry.

Signing ceremony:
1. Transfer the unsigned catalog to the established offline review machine.
2. Use the resident issuer fingerprint tool and a validator built with the
   Safe typed-call extension. Compare the fingerprint and every leaf with
   the reviewed source descriptors before bringing the printout to the issuer.
3. Sign the single Base-scoped catalog root with the established issuer,
   existing public issuer certificates and existing append-only ledger.
   Compare the physical issuer screens against the offline printout.
4. Verify the returned signed catalog against the production ClearSign root
   and this fingerprint before importing or serving any envelope.

The resident fingerprint tool prints a legacy "7.16 verifier" label. The
validator used for this new bundle is a development 7.17 build with capability
28 (SAFE_TYPED_CALLS), not stock 7.16. Its checksum is recorded in verification.json.
Stock 7.16 rejects the new typed embedded-call program.

Before wallet use:
- The connected owner KeepKey reports firmware 7.16.0. New on-device Safe
  inner-call review requires updated firmware with capability 28 and the
  corresponding Vault changes. No firmware was flashed during preparation.
- Review deployment/safe-deployment-review.json before authorizing deployment.
  Its nonce and fee estimates must be refreshed. Its value is zero; only the
  deployment fee is paid. The estimate excludes Base's L1 data fee.
- After deployment, verify implementation, both owners, threshold, handler,
  empty modules and absent guard on Base before activating the metadata.

No production metadata signature, Safe deployment, broadcast or service
publication has occurred in this preparation.
