## GATING — must pass before this RC ships upstream

**PR #272 — BIP-39 cipher recovery, wordlist validation, storage_reset/wipe gating.** A failure here loses funds or bricks recovery. Run every case; do not promote on any ⚠️.

> Requires repeated wipe/recover cycles. Have a KNOWN 12/18/24-word BIP39 test seed with precomputed master fingerprint + first BTC/ETH receive addresses. Also keep one valuable-but-known initialized wallet for the dry-run cases — **note its first BTC and ETH addresses before you start.**

- [ ] **G1 — Strict happy-path 12-word recovery.** Device wiped → start standard recovery (`enforce_wordlist=true`, non-dry-run), enter all 12 cipher words confirming each, finish → "Device recovered", device initialized, first BTC+ETH addresses and xpub fingerprint **exactly** match the known seed. ⚠️ valid word falsely rejected "Word not in wordlist", finish fails "Words were not entered correctly", or addresses/fingerprint differ.
- [ ] **G2 — Strict 18-word and 24-word recovery; last word via Done.** Device wiped → recover known 18-word, then known 24-word seed; finalize at least one by pressing **Done** on the last word (no trailing space) → both recover, addresses match each seed, Done-finalized last word is still validated. ⚠️ 24-word boundary rejected or wrong addresses; bad final word accepted via Done; storage_reset on a fully valid seed.
- [ ] **G3 — Invalid word mid-seed in strict real recovery.** Device wiped → enter 2-3 valid words, then a word whose decoded form is NOT a BIP39 word (cipher-encode "zzzz"), send the separating space → immediate "Word not found in BIP39 wordlist" / on-screen "Word not in wordlist"; recovery aborts; device stays uninitialized; a fresh recovery starts cleanly afterward. ⚠️ bad word silently accepted/auto-corrected, device hangs, or can't start a new recovery after.
- [ ] **G4 — CRITICAL: dry-run with garbage word must NOT wipe existing wallet.** Device INITIALIZED with known wallet → start Recovery **DRY-RUN** (`dry_run=true`, `enforce_wordlist=true`), enter a couple valid words then a non-wordlist/garbage word + space; also try finishing with a deliberately invalid seed → dry-run reports invalid/mismatch and fails gracefully; pre-existing wallet untouched; after reconnect the original first BTC/ETH addresses are unchanged. ⚠️ **any storage_reset during dry_run** — original addresses gone or device shows uninitialized.
- [ ] **G5 — Dry-run MATCH against device's own seed.** Initialized device with known seed → run dry-run, enter the EXACT on-device seed via cipher → "The seed is valid and MATCHES the one in the device."; wallet intact. ⚠️ reports mismatch/invalid for the correct seed, or wallet state altered.
- [ ] **G6 — Dry-run valid-but-different seed → mismatch, no wipe.** Initialized with seed A, have different valid seed B → run dry-run entering B → "The seed is valid, but DOES NOT MATCH the one in the device."; seed A still present (addresses unchanged). ⚠️ reported invalid, or device wiped/replaced with B.
- [ ] **G7 — Loose/import mode recovers a non-BIP39 seed (the flip fix).** Device wiped → start recovery with `enforce_wordlist=false`, enter a seed containing ≥1 non-wordlist word via cipher, finish → "Device recovered", storage marked imported, derives addresses from imported words. ⚠️ aborts/resets with "Words were not entered correctly. Make sure you are using the substitution cipher" — the old `!enforce_wordlist` finalize bug resurfaced.
- [ ] **G8 — Bad-checksum, all-valid-words strict seed rejected.** Device wiped → enter 12 individually-valid words with an INVALID overall checksum (swap last word of a known seed for another valid word), finish → "Invalid mnemonic, are words in correct order?"; storage reset; device uninitialized. ⚠️ device accepts and reports "Device recovered" (would derive a wrong/unsafe wallet).
- [ ] **G9 — Invalid LAST word via Done caught at finalize.** Device wiped, strict, word_count=12 → enter 11 valid words + a 12th that is NOT a valid BIP39 word, press **Done** (no trailing space) → finalize auto-complete fails → storage_reset + "Words were not entered correctly"; device uninitialized. ⚠️ invalid final word slips through (per-word check only runs on space) and a bad seed is accepted.
- [ ] **G10 — Previous-word OLED indicator renders correctly.** Device wiped, strict recovery → enter several words, watch top-left "(N.word)" indicator → word 1 shows NO indicator; from word 2 on, top-left shows "(N.fullword)" with correct 1-based prior index and the FULL auto-completed word (e.g. "(1.alcohol)" not "(1.alc)"); no overlap with cipher grid; "Recovery Cipher:" prompt legible. ⚠️ off-by-one index, raw typed prefix instead of full word, overlap/clipping/garble, or a stale word from a previous session.
- [ ] **G11 — Delete across a word boundary keeps indicator + final seed correct.** Device wiped, strict → enter 3-4 valid words, delete back across ≥1 word boundary, re-enter different valid words, complete a full valid seed → indicator updates/clears consistently with current position; recovery derives addresses of the FINAL entered seed. ⚠️ stale/incorrect prior word or wrong index after deletes; recovered seed/addresses don't match what was finally entered.
- [ ] **G12 — Non-cipher (raw-seed) entry still aborts (anti-footgun).** Device wiped, strict real recovery → deliberately type the actual seed letters WITHOUT the cipher for several words → after exceeding the uncyphered-word allowance, aborts "Words were not entered correctly. Make sure you are using the substitution cipher."; storage reset; stays uninitialized. ⚠️ raw non-ciphered entry now accepted (new per-word validation broke `definitely_using_cipher` detection), letting a seed be keyed in the clear.

## Session A — Boot / signature-verification (PR #271)

> Do this first after each flash so you confirm the RC boots clean before signing anything. Needs an initialized known wallet (BTC + ETH visible) for the storage-retention case. A flagged-bootloader unit and an unsigned build are optional but called out.

- [ ] **A1 — Signed RC happy-path boot.** Flash signed RC, let bootloader hand off, boot to home; power-cycle 10+ times → accepted silently every boot; no "Unrecognized firmware", no "Are you willing to take the risk?", no "Expired firmware". ⚠️ any boot shows the unsigned hash-confirm/expired screen, boot hang, or intermittent failure across the cycles.
- [ ] **A2 — Signed-to-signed update preserves storage (data-loss regression).** Initialized device on a current signed release with known seed/PIN + BTC+ETH accounts → flash this signed RC over it via normal vault update, reboot, unlock with existing PIN → "Firmware Update Complete", PIN unlocks, same seed fingerprint, same BTC/ETH addresses/balances. ⚠️ device asks to set up as new / recovery, PIN rejected, or addresses differ (hardened `signatures_ok()` wrongly triggered the unsigned-downgrade wipe).
- [ ] **A3 — Core signing correct after app-side verify removed (F5).** Initialized RC, real seed, vault → normal BTC send and ETH send, confirm amounts/addresses, broadcast (or sign-only + recover signer) → on-screen data correct; signatures valid, recover expected signer; tx broadcast normally. ⚠️ garbage on-screen data, invalid signature, or any signing crash (boot-time entropy/DRBG/stack-guard disturbed by F5 reordering).
- [ ] **A4 — Boot-time entropy/RNG integrity.** Signed RC freshly flashed, device wiped → run Create Wallet / reset, run entropy-dependent ops / self-test if available; reset twice and confirm the two generated seeds differ → seed generation succeeds, distinct valid seeds, no RNG/health-check failure. ⚠️ entropy/health failure, refuses to generate, or repeated resets produce identical/weak entropy.
- [ ] **A5 — (Optional unit) check_bootloader warning still fires on signed FW.** Device with a flagged-old bootloader (BLK_v1_x / v2_1_0–2_1_3) or unknown bootloader, running signed RC → boot, watch early screens → flagged → "Update Recommended"; unknown → "Unknown bootloader. Contact support." and halts. ⚠️ warning no longer appears on signed FW on a flagged bootloader (F5 sig-index gate silently went SIG_FAIL on a valid image).
- [ ] **A6 — (Optional) Unsigned firmware still gated, then runs degraded.** Locally-built UNSIGNED image, device in bootloader → flash it, read warning, confirm 4×8 hex hash, accept; boot and get an address → bootloader shows "Unrecognized firmware" + hash + "Are you willing to take the risk?"; declining aborts, accepting boots; app operates with sigRet=SIG_FAIL (check_bootloader skipped). ⚠️ unsigned FW boots with NO warning (gate bypassed), or app crashes/RNG fails after accepting.
- [ ] **A7 — (Only if a rebuilt bootloader is flashed) F3 hardened verify.** Rebuilt bootloader from stage/fault-injection, one correctly-signed FW + one byte-tampered copy → boot the signed one, then attempt the tampered copy → signed verifies and boots clean (double-SHA match, all three ECDSA pass, sentinel==3); tampered rejected with the risk-confirm screen. ⚠️ tampered boots without warning (accumulation/sentinel failed open) or correctly-signed rejected (constant-time memcmp/double-SHA false-mismatch). **If only firmware (not bootloader) was flashed, F3 is UNTESTED — flag explicitly.**

## Known limitations of this rehearsal RC

- **No version bump:** built at **7.14.1** (develop's declared version) with no bump for this RC. The Features version string will read 7.14.1 even though it carries 7.15-line changes (EIP-712, Insight clear-sign, TIP-712 gates) — do not rely on the reported firmware version to gate or identify this build.
- **device-protocol pinned to the fork branch:** message definitions come from the fork's `up/release-protocol` branch, **not yet on keepkey master**. New message types (e.g. GetBip85Mnemonic type 120, XRP memo, THORChain denom, Maya router) exist only on this pin; a host/SDK built against master protocol may not encode them.
- **Dev / unsigned build:** the device will warn **"unofficial firmware"** at boot and require accepting the firmware-hash risk prompt — this is expected for the rehearsal and is itself exercised by Session A. A production signed build must be re-tested for the silent-boot path (A1) before upstream ship.
- **#263 EIP-712 cancel propagation is believed non-functional** in this branch (review() always returns true; parseVals discards the cancel result) — only the strtoll input-validation behavior actually changes. Confirm and flag (C8/C9); do not treat the cancel feature as shipped.
- **#263 large uint256 (>2^63) still mis-encodes** via strtoll→LLONG_MAX (no ERANGE check) — C13 documents behavior rather than asserting a pass; decide separately whether real large-allowance flows are affected before ship.
- **#271 F3 (bootloader hardened verify) is only exercised if a rebuilt bootloader is flashed.** If only firmware was flashed, F3 is UNTESTED and must be run separately against a rebuilt bootloader build (A7).
